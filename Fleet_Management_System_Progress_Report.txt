COMPREHENSIVE PROGRESS REPORT

Report date: October 31, 2026

EXECUTIVE SUMMARY

The system is a Flask application with a JavaScript frontend and Supabase-backed
data and authorization. Recent work has focused on trip reporting and exports,
making historical trip records editable, adding duplicate-trip review, and
grouping report trips by driver name. The latest automated test run passed 138
tests.

Application code and database setup are separate deployment steps. Code
changes do not automatically apply database migrations or repair historical
data. Migration and setup instructions are documented in README.md.

TRIP REPORTS AND EXPORTS

The report module supports filtering by date range, driver, truck, trailer,
origin, destination, route, and trip status. It is designed to export all
matching records, not only the currently visible page.

The Excel builder creates six worksheets:
  1. All Trips
  2. By Driver
  3. By Origin
  4. By Destination
  5. By Truck
  6. By Trailer

The By Driver worksheet presents separate driver sections with their own trip
tables and summaries. Preview, Excel, and PDF group trips by normalized driver
name, so the same driver's trips are not split solely because their records
have different driver IDs. The PDF builder supports a selected grouping and
landscape trip tables.

Exports include trip details, odometer-based distance, group and overall
totals, and revenue fields where reliable revenue data is available.

REVENUE ACCURACY AND BLANK VALUES

Revenue is based on the saved hauling-rate snapshot and audited adjustments. It
is not estimated from fuel, salaries, or assumed rates. Trips that lack
required verified rate, trailer, or capacity data, are cancelled, or are
duplicate ISM records may have blank revenue. Blank values are excluded from
average-revenue calculations.

The report RPC and its revenue eligibility checks are defined in
supabase_trip_reports_migration.sql.

Historical trips with missing route or rate snapshots may need the documented
backfill in supabase_trip_route_rate_backfill.sql. The backfill preserves
uncertain records for review rather than guessing rates or trailer assignments.


HISTORICAL TRIP EDITING

Each row in the historical trips table has an Edit button that opens the
existing trip editor. The issue where clicking it did nothing was caused by the
Completed Trips page not including the details dialog required by that editor.
The dialog was added, a regression assertion was added, and the script URL
version was advanced to help bypass stale browser caching.

Saving uses the established update flow. Route number, pallet capacity, and
trip rate are resolved from route and trailer data rather than freely
overridden.
